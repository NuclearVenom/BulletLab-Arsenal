# BulletLab Arsenal Robot Package Specification

Version 1 — Arsenal Specification

---

## Overview

BulletLab Arsenal is a long-term robotics package ecosystem. This document is the authoritative technical standard that every robot package must meet. It governs package structure, metadata format, URDF rules, license policy, and the verification pipeline.

> [!IMPORTANT]
> A package must be:
> 
> - **Self-contained**: all URDF files and meshes are bundled in the package directory.
> - **Reproducible**: loads consistently across platforms without external paths or environment variables.
> - **Portable**: can be moved anywhere; requires no ROS installation or `package://` resolution.
> - **BulletLab-compatible**: every model is verified through `arsenal verify` (the official BulletLab Arsenal CLI).
> - **Cataloged**: perfectly synced with the [Arsenal Manifest Specification](manifest-spec.md).

---

## Package Design: Robot Families

A robot package represents a **robot family**, not necessarily one single robot model.

A single package may contain multiple URDF variants (models) that share the same mesh assets. For example:

<details>
<summary><b>Example: unitree_g1 package</b></summary>

```text
unitree_g1/
├── metadata.json
├── LICENSE
├── NOTICE.md
├── urdf/
│   ├── Unitree_G1_29DOF.urdf
│   └── Unitree_G1_26DOF.urdf
└── meshes/
    ├── torso.stl
    ├── left_leg.stl
    └── ...
```

</details>

The `metadata.json` file defines every installable model in the package. Each model entry points to a specific URDF file. This allows users to install a specific variant of a robot by its model ID.

### Optional Content

The following are allowed but not required and are not validated:

- `README.md`
- `docs/`
- `examples/`
- `textures/`
- `materials/`
- `images/`
- `videos/`
- Configuration files
- Demo programs

The validator ignores all optional content.

## The `urdf/` Directory

All URDF files must be placed inside a directory named exactly `urdf/`. No other directory name is accepted.

URDF filenames should preserve the real upstream name whenever possible. Do not rename every model to `robot.urdf`. Retain the original filename so that upstream references remain recognisable.

**Good examples:**
```
urdf/husky.urdf
urdf/Unitree_G1_29DOF.urdf
urdf/kuka_iiwa.urdf
urdf/ur5e.urdf
```

**Bad examples:**
```
robot.urdf          (wrong — not in urdf/ subdirectory)
urdf/robot.urdf     (wrong — information-free name)
```

### URDF Rules

| Rule | Requirement |
|---|---|
| Location | Must be inside `urdf/` |
| Filename | Preserve upstream name; lowercase or mixed case allowed |
| Mesh paths | Must be relative (e.g. `../meshes/base.stl`) |
| `package://` URIs | Forbidden |
| Absolute paths | Forbidden |
| External URLs | Forbidden |
| Xacro | Must be pre-processed to plain URDF before submission |

Mesh paths in the URDF must be relative to the URDF file's own directory. Because the URDF lives inside `urdf/`, a path like `../meshes/base.stl` refers to the `meshes/` directory at the package root.

---

## The Mesh Directory

The mesh directory must be named either `mesh/` or `meshes/`. No other name is accepted.

**Supported mesh formats:** STL, DAE, OBJ

**Naming conventions:** lowercase or original upstream naming is acceptable. Avoid spaces.

**Scale:** meshes should be in metres. Use the URDF `<scale>` attribute if the source geometry is in other units.

**Portability:** meshes must not contain embedded absolute texture paths.

## Metadata Specification

Every package must contain a `metadata.json` file at the package root. The file must conform to the JSON schema at `schemas/v1/robot.schema.json`.

### Full Example

```json
{
  "name": "unitree_g1",
  "display_name": "Unitree G1",
  "description": "Unitree Robotics G1 humanoid robot. Available in 29-DOF and 26-DOF configurations, sharing the same mesh library.",

  "version": "1.0.0",
  "arsenal_version": "1",

  "source": "https://github.com/unitreerobotics/unitree_ros",
  "license": "BSD-3-Clause",

  "authors": ["Unitree Robotics"],
  "maintainers": ["Your Name"],

  "tags": ["humanoid", "legged", "bipedal"],

  "minimum_bulletlab_version": ">=0.2.0",

  "models": [
    {
      "id": "29dof",
      "display_name": "29 DOF",
      "entrypoint": "urdf/Unitree_G1_29DOF.urdf",
      "default": true,
      "description": "Full configuration with 29 degrees of freedom."
    },
    {
      "id": "26dof",
      "display_name": "26 DOF",
      "entrypoint": "urdf/Unitree_G1_26DOF.urdf",
      "description": "Reduced configuration with 26 degrees of freedom."
    }
  ]
}
```

### Field Reference

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Unique package identifier. Pattern: `^[a-z0-9_]+$`. Must match the directory name exactly. |
| `display_name` | string | Yes | Human-readable name of the robot family. |
| `description` | string | Yes | Short paragraph describing the robot family, structure, and use cases. |
| `version` | string | Yes | Semantic version of the Arsenal package (e.g. `"1.0.0"`). |
| `arsenal_version` | string | Yes | Arsenal specification version. Must be `"1"`. |
| `source` | string (URI) | Yes | URL of the original upstream repository or source files where the robot was originally published. Do not put the URL of the BulletLab Arsenal package itself. |
| `license` | string | Yes | SPDX license identifier (e.g. `"MIT"`, `"Apache-2.0"`). |
| `authors` | array of strings | Yes | Original authors of the robot description. Preserve upstream attribution. |
| `maintainers` | array of strings | Yes | People responsible for this Arsenal package. |
| `tags` | array of strings | Yes | Discovery tags. Lowercase and hyphens only (e.g. `"wheeled"`, `"differential-drive"`). |
| `minimum_bulletlab_version` | string | Yes | BulletLab version requirement (e.g. `">=0.2.0"`). |
| `models` | array of objects | Yes | List of robot models in the package. At least one required. |

### The `models` Array

Each element in `models` describes one installable robot variant.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | string | Yes | Unique model identifier within the package. Pattern: `^[a-z0-9_]+$`. |
| `display_name` | string | Yes | Human-readable name for this model variant. |
| `entrypoint` | string | Yes | Path to the URDF, relative to the package root. Must begin with `urdf/`. |
| `default` | boolean | No | If `true`, this model is the default. Exactly one model per package must be the default. |
| `description` | string | No | Short description specific to this variant. |

### Schema Versioning Policy

The schema system is strictly versioned to ensure backward compatibility for all packages. 

**Structure:**
- Versioned schemas are stored under `schemas/v1/`, `schemas/v2/`, etc.
- The `schemas/latest/` directory always contains a copy of the newest stable schema.
- Every `metadata.json` should set its `$schema` key to the appropriate versioned raw GitHub URL (e.g., `https://raw.githubusercontent.com/NuclearVenom/bulletlab-arsenal/main/schemas/v1/robot.schema.json`).

**Migration & `arsenal_version`:**
The `arsenal_version` field corresponds to the schema version the package was built for (e.g., `"1"` for `v1`). When the specification introduces a breaking change, a new schema version (`v2`) is created. Older packages remain fully functional and are validated against their designated schema version. They only need to be updated to the newer `arsenal_version` if they are being actively modified to use new features.

## LICENSE Policy

> [!CAUTION]
> A `LICENSE` file at the package root is mandatory. Packages without a valid `LICENSE` file are hard-rejected.

### Automatic Classification

The validator reads the LICENSE file and classifies it automatically:

| Classification | Trigger text | Outcome |
|---|---|---|
| Permissive | MIT, Apache, BSD, ISC, MPL, Boost | Automatic pass |
| Copyleft | GPL, LGPL, AGPL | Founder Review Required |
| Unknown | No recognised signature found | Founder Review Required |
| Missing | File absent or empty | Hard failure — rejected |

### Founder Review Required

When a package is flagged for Founder Review:

- The verification pipeline continues and generates all reports.
- The package **cannot be auto-merged** into the registry.
- A project maintainer manually reviews the license and decides whether to accept the package.
- The final decision is recorded by the maintainer before merging.

This policy ensures the Arsenal registry does not inadvertently include copyleft-encumbered assets, while still allowing maintainers to make case-by-case decisions.

## NOTICE.md

`NOTICE.md` is mandatory. It must be present and non-empty. It must contain:

- **Original Project Name**: The name of the upstream project.
- **Original Source Repository**: URL of the upstream repository or release.
- **Original Authors**: Names of the original creators, if known.
- **Original License**: The license under which the upstream assets were released.
- **BulletLab Arsenal Modifications**: A description of changes made when porting the robot (e.g. removed xacro, converted meshes, restructured paths).
- **Redistribution Notes**: Notes on how the package may be redistributed.

## Two-Layer Verification Pipeline

### Layer 1 — Registry Validation

**Module:** `scripts/verification/registry.py`

**What it checks:**
1. Required files: `metadata.json`, `LICENSE`, `NOTICE.md`
2. Required directories: `urdf/`, and `mesh/` or `meshes/`
3. `urdf/` contains at least one `.urdf` file
4. `LICENSE` is non-empty and classified
5. `NOTICE.md` is non-empty
6. `metadata.json` is valid JSON with all required fields
7. Each model's `entrypoint` file exists on disk
8. URDF files are parseable XML with no forbidden path patterns and valid mesh references

**Exit codes:**
- `0` — all packages passed
- `1` — one or more hard failures
- `2` — one or more packages require Founder Review

### Layer 2 — Repository Identity Validation

**Module:** `scripts/verification/identity.py`

**Question answered:** Does every package and model have a unique, unambiguous identity across the entire repository?

This layer runs once across the full Arsenal before robot verification begins. It guarantees that future install APIs such as `Robot.install("unitree_g1")` always resolve to exactly one package.

| Check | Scope |
|---|---|
| Package name format | Per-package: valid characters, no whitespace |
| Reserved name rejection | Per-package: names from a fixed deny-list are rejected |
| Metadata name ↔ folder | Per-package: `metadata["name"]` must equal the directory name |
| Category-level uniqueness | Per-category: no duplicate folder names |
| Global namespace uniqueness | Cross-category: names must be unique across ALL categories |
| Display name advisory | Global warning if two packages share a `display_name` |
| Model ID uniqueness | Per-package: no duplicate model `id` values |
| Model display_name advisory | Per-package warning for shared model display names |
| Model entrypoint uniqueness | Per-package: no two models may share an entrypoint |
| Entrypoint validity | Per-package: path exists, inside `urdf/`, cannot escape the root |
| URDF coverage | Per-package: every `.urdf` in `urdf/` belongs to exactly one model |
| Manifest consistency | Global: generated manifests match the on-disk package set |
| Install namespace simulation | Global: `Arsenal.install(name)` resolves to exactly one target |

**Reserved package names:**

The following names are permanently reserved and can never be used as a package identifier:

```
robots, worlds, sensors, controllers, datasets, benchmarks,
install, fetch, verification, manifest, metadata, license,
readme, package, schema, scripts, docs, src,
arsenal, registry, index, core
```

### Layer 3 — BulletLab Verification

**Module:** `scripts/verification/robot.py`

For each model in `metadata.json`:
1. A headless BulletLab simulation is started (DIRECT mode, zero gravity).
2. The model is loaded via `Robot.load()`.
3. The robot AABB is computed and the robot is repositioned at Z = 0.
4. All link and joint information is extracted from PyBullet.
5. Every revolute and prismatic joint is exercised through its range of motion.
6. A 60-step stability simulation is run; NaN values cause a failure.
7. 7 reproducible screenshots are rendered from fixed camera angles.
8. Results are written to `verification/`.

**Output files per package:**
- `verification/verification_report.json` — machine-readable per-model results
- `verification/robot_summary.md` — human-readable summary of all models
- `verification/screenshots/<model_id>/` — 7 PNG files per model

> [!WARNING]
> **The verification system is the sole source of truth for official previews and robot statistics.** Contributors are allowed to include their own images or screenshots in the package folder for future users, but these cannot replace the official auto-generated screenshots. Do not submit robot statistics computed outside BulletLab.

### Arsenal CLI (Official Entry Point)

BulletLab Arsenal ships as an installable Python package. After `pip install -e .` from the repository root, the `arsenal` command is available system-wide.

```bash
# Verify a single package:
arsenal verify robots/unitree_g1

# Verify all packages (CI mode):
arsenal verify-all

# Skip simulation (structure checks only, no PyBullet required):
arsenal verify robots/unitree_g1 --skip-simulation

# Identity + registry validation only:
arsenal validate robots/unitree_g1

# Regenerate manifests:
arsenal manifest

# Show repo info:
arsenal info
```

**Exit codes:**
- `0` — all packages passed (auto-mergeable)
- `1` — one or more packages failed (blocked)
- `2` — one or more packages require Founder Review (blocked until manual review)

<details>
<summary><b>Alternative: run the orchestrator script directly (CI / no install)</b></summary>

In environments where `pip install` is not available (e.g., lightweight CI containers), the underlying orchestrator script can be called directly:

```bash
python scripts/run_verification.py robots/unitree_g1
python scripts/run_verification.py --all
python scripts/run_verification.py robots/unitree_g1 --skip-simulation
```

</details>

## Submission Checklist

- [ ] Package directory name is lowercase, alphanumeric, underscores only.
- [ ] All URDF files are inside `urdf/`.
- [ ] URDF filenames preserve the original upstream filename.
- [ ] Mesh directory is named `mesh/` or `meshes/`.
- [ ] All URDF mesh paths are relative; no `package://`, no absolute paths.
- [ ] No `xacro` — plain URDF only.
- [ ] `metadata.json` is complete: all required fields, valid `models` array, one `"default": true`.
- [ ] Each model `entrypoint` begins with `urdf/` and the file exists.
- [ ] `LICENSE` is present, non-empty, and uses a recognised license.
- [ ] `NOTICE.md` is present, non-empty, and contains all required sections.
- [ ] `arsenal verify robots/<package>` passes.
- [ ] The `verification/` directory has been committed to the repository.
